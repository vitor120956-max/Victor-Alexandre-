O QUE FOI USADO
---------------
Apenas o DESENHO descrito publicamente no repositório e nos módulos citados,
reimplementado em Python sem copiar nenhum arquivo do upstream e sem adicionar
dependência:

- as quatro operações públicas `remember`, `recall`, `improve` e `forget`
  (`cognee/api/v1/`), usadas como vocabulário das sete skills desta camada;
- o portão determinístico de skill do `recall()`
  (`cognee/api/v1/recall/skill_gate.py`): regras de expressão regular com peso,
  sinal forte que decide sozinho, sinal fraco que só soma, limiar de disparo e
  janela de negação de 20 caracteres antes do casamento;
- o vocabulário de vias de busca (`cognee/modules/search/types/SearchType.py`)
  e o critério “em que cada tipo é bom” do prompt de seleção
  (`cognee/infrastructure/llm/prompts/search_type_selector_prompt.txt`),
  traduzidos para oito vias com peso lexical em vez de escolha por LLM;
- o conjunto de nós por sessão e a destilação de lição da sessão em memória
  permanente (`improve`, `SessionNodeSetEntry` em `cognee/memory/entries.py`);
- o escopo de esquecimento do `forget()` — item, dataset, tudo — e a opção
  `memory_only`, que remove grafo e vetor e preserva o arquivo bruto;
- o formato de memória tipada com `type`, `id` e `dataset`, usado como
  referência do formato `id | tipo | criado | fonte | dataset | texto`.

O QUE NÃO FOI USADO
-------------------
- Nenhum arquivo Python, frontend, Dockerfile, conector, plugin ou servidor MCP
  do upstream foi copiado para este repositório.
- O pipeline de ingestão, o `cognify`, os bancos (Kuzu, pgvector, Postgres),
  a API REST, o MCP e o plugin do Claude Code não foram reproduzidos.
- Nenhum modelo de linguagem, embedding, extração com GLiNER ou avaliação
  BEAM é chamado: a camada é lexical e determinística.
- O formato COGX de migração de outras memórias (Mem0, Letta, Zep, Graphiti)
  não foi portado.
